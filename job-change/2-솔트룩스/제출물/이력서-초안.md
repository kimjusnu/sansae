## [자기소개] — 폼 최상단, 3문장

전국 130여 농가·1,200여 사료빈을 모니터링하는 축산 IoT SaaS의 웹 개발을 2인 체제에서 맡고 있습니다(전체 커밋의 약 38%). 기존 이미지 분석 AI(SAM)의 한계를 발견해 SAM2 교체를 직접 제안·적용해 분류 오류율을 10%에서 3%로 낮췄고, npm 주간 최대 127,000회 다운로드된 오픈소스 UI 컴포넌트 라이브러리를 설계했습니다. AI 기술을 사용자가 실제로 쓰는 화면과 서비스로 만드는 일을 매일 하고 있습니다.

## [지원동기] — 자기소개 직후 배치 (폼에 별도 란이 없으면 자기소개에 이어 붙임)

공고를 보니 Agent Studio·Document Studio처럼 AI 기술을 노드 기반 워크플로우 UI와 완성도 높은 제품으로 만드는 것이 Product Center의 핵심 업무인데, 제가 지금 하는 일이 정확히 그 앞 단계입니다. LLM과 이미지 분석 AI를 실사용 SaaS에 통합해 왔고, 30개 이상의 컴포넌트로 디자인 시스템을 구축·운영해 봤으며, Tiptap 기반 12단계 저작 에디터를 설계한 경험이 있습니다. 이 세 경험이 각각 공고의 'AI 서비스 연동 화면', '공통 UI 컴포넌트·디자인 시스템 구축·운영', '노드 기반 에디터 개발'에 대응한다고 판단해 지원합니다.

## [경력 1] 에임비랩 — 주임연구원(정규직), 2025.07 ~ 재직 중

**담당**: 축산 IoT SaaS 'My Feed' 웹 개발 (2인 체제, 본인 커밋 약 38%) · 회사 홈페이지 전면 리뉴얼 단독

수행업무:
- 기존 이미지 분석 AI(SAM)의 낮은 정확도를 문제로 정의하고 직접 대안을 조사, SAM2 교체를 제안·적용해 분류 오류율 10%→3% (오분류의 수동 검수 유입 비율로 측정)
- 브라우저 업데이트로 웹푸시가 끊기는 장애를 OS 이벤트 로그 기반 홉 단위 추적으로 원인 특정, 가설 4개를 실험으로 배제 후 푸시+폴링+복귀 갱신 3중 방어 구조 설계 — 모든 브라우저에서 알림 도달 보장
- 백엔드 스펙이 서버 구현보다 앞선 상황에서 feature-detection 전방호환 설계 — 백엔드 배포 시점과 무관하게 프론트 재배포 0회
- 모니터링 상세 API N+1 제거(3개월 조회 기준 DB 왕복 약 2,400회→1회), 관리자 이미지 목록 172초→수 초, 62개 화면 공통 로드 139KB 절감
- 주문 문의 멱등키·기준사진 낙관적 잠금 설계 (파괴적 액션 자동 재전송 금지 원칙)
- 레거시(Jinja SSR+vanilla JS) 구조의 한계를 느껴 Next.js 16+React 19 기반 v2 마이그레이션 시제품을 자발적으로 구축 (Recharts·TanStack Query·Zustand·Zod, Vercel 배포+pre-push 로컬 CI)
- 홈페이지 리뉴얼(단독): Next.js App Router·RSC 재구축, 월 최대 1건이던 고객 문의를 월 평균 9건 체계로 전환, 실제 계약 성사 기여. 번역 API 429 문제를 자체 i18n으로 해소. LCP 3.97s·INP 392ms 실측 후 성능 개선 과제 도출

**담당**: 창업 교육 퀴즈 저작·검수 SaaS 'StartupQT' FE 전반 + 배포 파이프라인 단독 구축

수행업무:
