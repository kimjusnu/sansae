## 2. 요건 vs 내 스펙 — 이 공고는 매칭이 이례적으로 좋다

| 채널톡 FE 업무 | 내 실증 경험 | 매칭 |
|----------------|--------------|------|
| **디자인 시스템 개발** | **Componique — 오픈소스 디자인 시스템 30+ 컴포넌트, npm 주간 127K** | 🟢🟢 직결 |
| **에디터 개발** | **StartupQT — Tiptap 기반 모듈형 에디터 + 검수 워크플로우** 실무 구축 | 🟢🟢 직결 |
| 채팅 위젯 (고객사 웹 삽입) | 위젯 실무는 없으나 라이브러리 번들링(Rollup)·임베드 관점 유사 경험 | 🟡 |
| AI 메신저 (회사 정체성) | LLM 통합 실무 — 분류 오류율 10%→3% | 🟢 |
| CS 전공 | 한국공학대 컴퓨터공학부 소프트웨어전공 | 🟢 |
| 자료구조·알고리즘 | 전공 이수 — 단 **라이브 코딩 전형 대비 필요** | 🟡 준비 필요 |
| 빠른 학습 | RSC 도입, 자체 i18n, Vue→Next 마이그레이션(Wairi) | 🟢 |

**핵심 서사**: 채널톡 FE의 3대 업무(디자인시스템·에디터·위젯) 중 2개를 이미 실무/오픈소스로 해봤다 — 이 각도로 이력서 전체를 재배치.

## 3. 리스크 & 대응
| 리스크 | 대응 |
|--------|------|
| **1차 PS 라이브 코딩** | 지원 전 1~2주 알고리즘 리프레시 권장 (자료구조·문자열·그래프 기본). 지원 시점 조절 가능 — 수시라 마감 압박 없음 |
| 위젯 경험 공백 | 거짓 금지. Rollup 번들링·SDK 관점으로 유사성만 언급 |
| 풀스택 포지션 가능성 | FastAPI·Docker·CI/CD 경험으로 오히려 유리 |

## 4. 전형 대비 메모
- 사전 기술 인터뷰(30~45분): Componique 설계 결정(왜 Rollup, 트리셰이킹, 버저닝)과 StartupQT 에디터 아키텍처 설명 준비
- 2차 기술 토론: 디자인 시스템 API 설계 / 에디터 상태 관리(Zustand) 심화
- 3차 컬처핏: "단일 스택에 묶이지 않는다" 문화 ↔ FE→AI→인프라 확장 스토리
